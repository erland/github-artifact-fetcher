# DEV-005 – GitHub App OAuth, identitet och tokens

Implementerat:
- `/auth/github/start`, `/auth/github/callback`, `/auth/logout` med engångs-state och kortlivad, HttpOnly/Secure/SameSite-cookie.
- Efter GitHub Apps användarauktorisering hämtas det stabila numeriska GitHub-användar-ID:t från `/user`; subjektet blir `github:<id>`, aldrig e-postadress.
- Betrodda inloggningssessioner i PostgreSQL (endast SHA-256-hash av sessions-ID).
- GitHub access/refresh-tokens krypteras med AES-256-GCM och 32-bytes `ENCRYPTION_KEY`; ciphertext lagras i `github_connections`.
- GitHub-token uppdateras vid behov med en transaktionellt låst rad och förnyat refresh-token, utan att lämna ut token via MCP.
- Kontroll av tillgång till specifikt repository via GitHubs autentiserade REST API; fel/404 innebär nekad tillgång. Denna kontroll ersätter inte GitHub Apps installationsbehörigheter eller framtida API-anrop per fil.
- OAuth-serverns principal-resolver hämtar identitet från autentiserad sessionscookie, inte anropsparametrar.
- Flyway V4 tillför sessionhashar och OAuth state samt separat sparande av GitHub-användar-ID och krypterat refresh-token.

Konfiguration:
- `DATABASE_URL`
- `PUBLIC_BASE_URL` – HTTPS ursprung
- `GITHUB_APP_CLIENT_ID`
- `GITHUB_APP_CLIENT_SECRET`
- `ENCRYPTION_KEY` – base64-kodad nyckel som avkodas till 32 byte

GitHub App callback ska registreras som `<PUBLIC_BASE_URL>/auth/github/callback`. Exponera inte dessa värden i loggar. Rotera krypteringsnyckel via en uttrycklig migreringsprocess, inte genom att bara ändra miljövariabeln.

**Viktigt:** Ingen extern GitHub-inloggning, installation, rättighetsstyrning för GHCR, samtyckes-UI eller ChatGPT OAuth end-to-end är verifierad. Åtkomstgranskning, CSRF-skydd vid fler användaråtgärder, rate limits, auditloggning, samtycke och säker kontorevokering krävs före publik drift. Ingen driftsättning.
