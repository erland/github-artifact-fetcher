# DEV-009 – Säkerhetshärdning, hotgranskning och regression

## Implementerat
- Central säkerhetspolicy för HTTPS-omdirigeringar med exakta tillåtna hostnamn, utan URL-inloggningsuppgifter, portar eller fragment. Kontrolleras för Releases, Actions och repositoryarkiv.
- Gemensam Content-Length-validering: negativa, ogiltiga, överstora och icke-säkert representerbara värden nekas. Strömmande nedladdningar är sedan tidigare begränsade till 20 MiB.
- Avvisar HTML-svar och uppföljande redirects vid filhämtning.
- HTTP-säkerhetsheaders: nosniff, no-referrer, DENY-frame, CSP och no-store.
- Fastfönsterbegränsning på 120 HTTP-anrop per minut och peer-adress, med 429 vid överskridande. Detta är en enkel instanslokal skyddsåtgärd, inte distribuerad anti-abuse.
- Strukturerad säkerhetslogg med request-ID, händelse och status utan credentials eller filinnehåll.
- OAuth: explicit avvisning av okända grant types och begränsad state-längd.
- Negativa regressionstester för SSRF, falska värdnamn, credentials i URL, ogiltig Content-Length, oväntat HTML-svar, rate limiting och headers. Tidigare OAuth- och användarisoleringstester finns kvar.

## Risker och releaseblockerare
1. OAuth /authorize saknar uttryckligt UI-samtycke per klient och dynamisk registrering har ännu inte fullständig anti-abuse-policy. Måste lösas innan en publik OAuth-endpoint exponeras.
2. Rate limiting är instanslokal och kan orsaka minnesökning vid många unika adresser; proxy- och distributed policies behöver beslutas innan fler repliker.
3. Identity-session, OAuth-grants och reell tokenåterkallelse/installsbehörigheter behöver verifieras end-to-end, inklusive GitHub App-revokering och användarisolering.
4. ZIP-valideringen verifierar signatur men inte central directory, antal poster eller zip-bomb. Filarkiv packas inte upp.
5. GitHub CDN-endpoints verifieras mot allowlist men ingen liveacceptans är gjord; DNS/IP-kontroller och redirectpolicy behöver kompletterande granskning i driftsmiljön.
6. 20 MiB Base64-transporter riskerar stora MCP-svar; arkitekturen måste ersättas med kontrollerad filöverföring och ChatGPT-native file handoff före release.
7. Loggretention, begränsningar per användare/klient och strukturerad auditkorrelation kräver operativ konfiguration.

Ingen driftsättning genomförd. DEV-010 får inte sättas till releasable innan risker och externa acceptanstester har hanterats.
