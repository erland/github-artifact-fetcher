# DEV-007 – GitHub Actions Artifacts

## Levererat
- MCP-verktyg `list_workflow_artifacts` och `fetch_workflow_artifact` med verifierat positivt workflow run-ID och artifact-ID.
- GitHub REST API `actions/runs/{run_id}/artifacts` med upp till tio sidor och `actions/artifacts/{artifact_id}/zip`.
- Åtkomst till repository verifieras mot den autentiserade användarens GitHub-konto före API-anrop. Artifact-ID måste återfinnas inom begärt workflow run-ID innan hämtning tillåts.
- Utgångna artifacts spärras baserat på `expired`, `expires_at` eller HTTP 410.
- Nedladdning sker enbart från GitHub API och strikt allowlistade HTTPS-omdirigeringar. Bearer-token vidarebefordras aldrig till nedladdningsvärden. Högst en omdirigering.
- Skydd mot för stora payloads (20 MiB), med kontroll både före nedladdning och under strömning, timeout samt kontroll av ZIP-signatur.
- Nedladdade bytes returneras som base64 med beräknad SHA-256 och storlek. `size_in_bytes` från GitHub jämförs inte direkt med ZIP:ens storlek eftersom de kan skilja sig.

## Avgränsningar
- GitHub REST API och nedladdningar är verifierade med simulerade svar, inte ännu med ett riktigt GitHub Actions-artifact.
- ZIP-signaturen kontrolleras, men fullständig ZIP-strukturskanning, zip-bombanalys och säkert uppackande ingår inte i detta steg. Inget arkiv packas upp av tjänsten.
- Tillåtna CDN-hostnamn kan behöva utökas efter kontrollerad liveverifiering utan att godtyckliga redirect-värdar tillåts.
- MCP returnerar base64, inte en verifierad ChatGPT-intern filbilaga. Detta är en kvarstående releaseblockerare från DEV-001.
- 20 MiB-gränsen gäller denna implementation. Inga produktionssystem har driftsatts.
